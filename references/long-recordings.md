# 长录音与长文字稿

## 已实现的音频路径
脚本先探测时长，再固定 300 秒分段（可设 30–600 秒），转为 16kHz 单声道 PCM WAV。总时长无业务限制，单段控制常见上传大小；硬件、磁盘、费用和服务配额仍有限制。逐段顺序执行，成功结果落检查点，失败停止并报告剩余范围。相同输入哈希与参数可恢复。

**首版无重叠分段，不承诺无损边界词、不自动合并说话人身份。** 抽查每个分段边界、短句、数字和末尾。未来可增加基于停顿的切分及可核查的重叠去重；目前不得描述为已完成。

成功空段记录警告；不声称静音判断已验证。断网/超时后重新调用可能产生重复计费，因为服务端是否已完成不可确定。脚本关闭 SDK 自动重试。

本地参数 device/model/compute_type 改变时需新输出目录。完整 source.json 会随进度更新，巨大输入仍可能遇到 JSON 内存/磁盘限制；首版不是无限流系统。

## Agent 处理全文
1. 用宿主可读的批次按源段落 ID 顺序读取，维护 last_read_id 和批次范围，不跳页。
2. 每批保存事实索引：原文陈述/观点/提议/决策/承诺、数字及口径、来源 ID、疑义。
3. 每批产出整理全文段落，来源映射不可丢失。
4. 跨批合并主题，不只将多个压缩摘要再压缩。遇到冲突回到源段落核对。
5. 全文覆盖检查：所有实质段落已整理，所有批次已纳入事实索引；引用可定位。
6. 检查后面的否定/修正是否推翻前面提议，避免只保留最早说法。
7. 停止或上下文不足时保存 progress.json（放工作目录、不得公开），列出尚未读完的范围；result.status=partial。

检查点和完整稿均含敏感资料。项目不自动清理，用户可按 PRIVACY.md 在系统中手动处理。不能以“我们不上传音频”暗示云端总结不外传文字。
